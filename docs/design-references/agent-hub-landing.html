Capabilities

What the current code actually does, stated at the level the implementation supports.

Route models in Claude Code

Bind Fable, Opus, Sonnet and Haiku slots to different providers and models. Switch between them with Claude Code's native /model command.

Bridge provider APIs

Use Anthropic-native upstreams directly, or translate Claude Code traffic to OpenAI Chat Completions and Responses, including streaming and tool calls.

Define fallback paths

Configure fallback routes and compatible account pools with explicit retry and replay boundaries.

Inspect runtime behavior

Review token usage, cache behavior, provider attribution and redacted gateway failures without storing complete request or response bodies.

Launch isolated Codex sessions

Select a provider for one Codex session through a temporary CODEX_HOME. Your normal Codex configuration and credentials remain untouched.

Manage providers once

Add providers directly to Agent-Hub or import compatible records from JSON or CC Switch.

Two runtimes, deliberately different

Claude Code can use the Agent-Hub gateway. Codex keeps its native runtime and receives only an isolated session configuration.

What happens to one Claude Code request

The gateway is a local process between the CLI and the upstream provider. It resolves a slot, translates the wire format when needed, and records what happened — without keeping the conversation.

Current boundaries

Stated plainly, because knowing them early is cheaper than discovering them later.

  • The desktop release targets Apple Silicon macOS, ad-hoc signed, not notarized There is no published Windows installer; Windows source is maintained separately. Scheduled desktop actions run only while Agent-Hub is open.
  • Codex does not use the gateway Codex sessions currently get isolated provider launches only — no protocol bridge, no account pools, no fallback routing.
  • Interrupted streams stay failures A truncated stream is never completed with a synthetic stop event, and a lost tool call is never reported as completed. Upstream errors stay visible after credential redaction.
  • Credentials stay out of normal output Provider state lives in a local 0600 database. Credentials are excluded from provider list output, desktop responses and error records.
